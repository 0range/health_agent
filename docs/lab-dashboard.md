# История анализов по профилю

Коротко: дашборд показывает только подходящие подтверждённые анализы выбранного
профиля. Каждый график — один аналит и одна исходная единица, результат и референсы
на общей оси. Импортированные файлы и ожидающие проверки кандидаты не означают,
что весь архив уже представлен на графиках.

Подготовить или обновить дашборд и сохранить прямую ссылку для панели:

```bash
uv run health-agent dashboard setup-labs --profile-id PROFILE_UUID
```

Команда вызывает `bootstrap_lab_dashboard(settings, profile_id, *, transport=None,
engine=None)`, создаёт отдельный дашборд `Анализы крови — история [полный UUID]`
и сохраняет его адрес для этого профиля. В панели появляется ссылка «Анализы»;
WHOOP остаётся отдельным дашбордом и отдельной ссылкой. Старый дашборд
`Анализы крови` не изменяется. Команда действительно обращается к настроенному
Metabase, поэтому это не сухой прогон.

Первой идёт таблица последних 1000 результатов с точной строкой результата,
единицей, напечатанным референсом и флагом, идентификатором документа и страницей.
Далее — два графика на строку, каждый для одного аналита и одной единицы.
Графики включают всю доступную подходящую историю; SQL не усредняет и не объединяет
повторные результаты одного дня. Такие измерения получают отдельные подписи даты
с порядковым номером. Ось дат категориальная: расстояние между точками не кодирует
число прошедших дней. Точки включены, пропуски не заменяются нулями, результат и
обе границы референса используют одну левую ось, автоматическое разделение отключено.

Создаются только реально доступные зарегистрированные пары «аналит — единица»,
до 80 серий. Для присутствующих популярных исследований применяется привычный
порядок (ферритин, B12, фолат, витамин D и другие); остальные пары идут в стабильном
порядке. Обязательного набора из 13 пустых графиков больше нет. Без подходящих
результатов остаётся пустая таблица с пояснением. Незарегистрированные пары в
историю не попадают; после появления новой серии повторите команду подготовки.

## Числа и референсы

Источник — `verified_lab_history` только выбранного профиля: документ обработан,
без безопасного кода ошибки, медицинская дата известна и не в будущем.
Нечисловые/квалифицированные (`<40`) строки, несоответствие исходной строки
`parsed_value`, неограниченные, нечисловые и бесконечные числа исключаются.
Числа ограничены модулем 10¹² и точностью до 12 десятичных знаков.

Графики используют **число в исходной единице**, объединяя только написания
одного семейства из реестра (`нг/мл` → `ng/mL`). Физические конверсии не
выполняются: `mg/dL` и `mmol/L`, а также отдельные семейства `ug/L` и `ng/mL`
остаются отдельными графиками. Так напечатанные границы не оказываются на оси
пересчитанного результата. Сохранённое нормализованное значение тоже должно
быть конечным и ограниченным, но для графика оно не используется.

Границы и сравнение «Ниже референса» / «В референсе» / «Выше референса» доступны только когда исходный референс
целиком является простым двухсторонним числовым диапазоном и совпадает с обеими
сохранёнными границами. Одиночная граница, отсутствующий, текстовый, имеющий
явно указанную единицу или неоднозначный диапазон дают «Не определено», не «В референсе».
Это консервативное числовое сравнение, а не диагноз или медицинский совет.
Исходные строки результата, единицы, референса и флага остаются в таблице независимо
от возможности сравнения. Полный текст медицинского документа таблица не публикует.

## Владение и повторный запуск

Полный UUID присутствует в названиях и SQL. Для изменения существующей карточки
нужны точное имя, коллекция, база и точный SQL текущей или явно поддержанной
предыдущей версии; одноимённая
чужая или изменённая SQL-карточка вызывает ошибку без перезаписи карточек.
Проверка учитывает обычный и staged native-query ответ Metabase.
Визуальное оформление собственных карточек восстанавливается при повторе.

Если наблюдаемая серия исчезла или больше не помещается в лимит, только точно
проверенная собственная карточка отсоединяется от дашборда; сохранённая карточка
не удаляется. Пользовательские карточки и настройки сохраняются. При пересечении
с сеткой истории их группа сдвигается вниз с сохранением взаимного расположения.
Точные прежние запросы с английскими сравнениями и прежней осью повторных дат
поддерживают проверенный переход при повторном запуске. Произвольный изменённый
SQL не присваивается приложению; дальнейшие версии могут требовать отдельного
явно проверенного перехода.

Подключение к PostgreSQL для обнаружения серий выполняет только SELECT.
Подготовка существующей роли `health_dashboard` и ресурсов Metabase использует
общие проверенные функции проекта. Переданный движок не закрывается; временный
собственный движок закрывается. Это не отдельная граница авторизации Metabase:
доступ пользователей к коллекции и базе по-прежнему настраивает администратор.

Сам дашборд не отправляет документы в AI и не требует облачного извлечения.
Если используется Yandex для отдельного извлечения кандидатов или ответов,
действуют [настройка провайдера и явное согласие профиля](yandex-ai.md);
кандидаты всё равно требуют проверки.

Автоматические проверки используют одноразовый PostgreSQL с синтетическими
данными и `httpx.MockTransport`, без живого Metabase и личных медицинских документов.
Они не заменяют отдельную проверку доступа и отображения реального дашборда.
