# Health Agent: локальная management-панель

> **TL;DR:** одна простая страница на Mac для профилей, подключений и состояния синхронизаций. Медицинские графики остаются в Metabase, вопросы — в Telegram.

## Зачем она нужна

Панель отвечает только за управление системой:

- добавить или отключить профиль;
- подключить WHOOP и Google;
- добавить ссылки на папки Google Drive;
- привязать Telegram ID;
- увидеть свежесть данных и понятную ошибку;
- вручную запустить синхронизацию или переподключение.

Она не заменяет Metabase, Google Sheets или Telegram и не пытается быть медицинским кабинетом.

## Экран первой версии

Одна локальная страница `http://127.0.0.1:<port>`:

1. Список профилей.
2. Внутри профиля — карточки WHOOP, Google Drive/Gmail и Telegram.
3. В карточке подключения — аккаунт, статус, последняя успешная синхронизация, количество новых объектов и последнее требуемое действие.
4. Действия: `Подключить`, `Добавить папку`, `Синхронизировать`, `Переподключить`, `Отключить`.

Обычный успешный sync пользователя не тревожит. Ошибка показывается в панели; Telegram-сообщение отправляется только когда без пользователя продолжить нельзя.

## Профили и изоляция

- Одна установка на Mac обслуживает несколько профилей.
- У каждого профиля отдельные WHOOP/Google-аккаунты, папки Drive и Telegram ID.
- Любой документ, показатель, сырой ответ, напоминание и sync-run содержит `profile_id`.
- Дедупликация действует внутри профиля; одинаковый файл у двух людей не связывает их данные.
- Telegram ID однозначно определяет профиль. Ответы не используют данные другого профиля.
- Переключение профиля в Metabase выполняется явным фильтром; общий вид не является вариантом по умолчанию.

## Требования к Google Drive

- Пользователь вставляет ссылку на одну или несколько корневых папок.
- Google-аккаунту достаточно доступа на чтение; публичная ссылка не нужна.
- Коннектор рекурсивно обходит подпапки. Строгая структура и имена файлов не обязательны.
- В первой очереди поддерживаются PDF и изображения; Google-native документы обрабатываются только через явный безопасный export.
- Health Agent не создаёт, не изменяет, не перемещает, не расшаривает и не удаляет файлы на Drive.
- Первичная синхронизация собирает доступную историю. Затем используются изменения Drive и периодическая страховочная сверка.
- Повторный файл не создаёт новый медицинский документ, но новый источник обнаружения сохраняется.
- Если файл недоступен, слишком велик, повреждён или требует OCR, это становится машинным статусом, а не тихим успехом.

## Подключение аккаунтов

- Авторизация выполняется только на официальной странице WHOOP или Google.
- Пароли Health Agent не получает.
- OAuth-токены хранятся локально по профилю в исключённых из Git файлах с правами `0600`.
- Management-панель никогда не показывает client secret, access token или refresh token.
- Локальный callback слушает только `127.0.0.1` и живёт только во время подключения.

## Минимальная модель

- `profiles` — человек и его локальные настройки;
- `connector_accounts` — профиль, провайдер, внешний account ID, OAuth-статус;
- `drive_roots` — профиль, Google-аккаунт, folder ID, подпись и активность;
- `telegram_identities` — профиль и разрешённый Telegram user ID;
- `sync_runs` — источник, время, cursor, количество новых/обновлённых объектов, безопасный статус ошибки;
- `action_required` — конкретное действие, без секретов и медицинского текста.

## Граница v0.1

Панель считается готовой, когда с неё можно создать второй профиль, подключить два разных WHOOP/Google-аккаунта, добавить разные Drive-папки, привязать разные Telegram ID и увидеть независимые статусы синхронизации. Редактирование медицинских данных и просмотр графиков остаются за пределами панели.
