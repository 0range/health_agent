# Сон: релевантные факты и честная неопределённость

TL;DR: не меняем модель вслепую. Убираем нерелевантные данные из запроса,
не используем старые ответы бота как доказательства, проверяем ответы на регрессии.
Пользователь прямо потребовал исправить выдуманные объяснения и продолжать без
ненужного вовлечения; это реализация этого требования, не новый продуктовый выбор.

Доказанный дефект: текущий SleepCoach получает общий snapshot с историческими
анализами и нерелевантными reported_material; затем передаёт собственные прошлые
ответы как обычный контекст. Ответ присвоил старому показателю новую дату и
использовал WHOOP/анализы для необоснованного отрицания болезни.

Варианты: только усилить промпт (не убирает плохой контекст), сменить модель
(не исправляет смешение источников), ограничить контекст и проверять ответ.
Выбран третий, без нового сервиса или миграции.

Для вопросов о нынешнем сне/сонливости/усталости: актуальные измерения сна и
восстановления, датированные слова пользователя. Старые анализы и посторонние
заключения не передавать. Если пользователь явно спрашивает об анализах,
добавлять соответствующие свежие результаты с собственными датами; исторические
сравнения доступны только при явном запросе, не как объяснение нынешнего состояния.
Разговор сохраняется в базе полностью, но прежние выводы ассистента не являются
медицинскими доказательствами и не должны повторно загрязнять генерацию.

Когда спрашивают причину нынешней усталости, инфекцию или погоду, приложение
не устанавливает причину и не исключает заболевание по WHOOP/нормальным анализам.
Ответ короткий: что неизвестно, максимум одно релевантное наблюдение с собственной
датой, один полезный вопрос/следующий шаг. Вопрос «есть температура?» не повторять,
если пользователь уже ответил. Неподдержанный ответ заменять честным уточнением.
Одного JSON или наличия source ID недостаточно для доказательства смысла фразы:
для причинного объяснения использовать ограниченный проверяемый формат, а не
свободный медицинский вердикт модели.

Сохраняются общий медицинский доступ основного бота, дневник, цели, защита срочных
симптомов, границы профилей и повторная доставка. Архив/старые ответы не удаляются.
Не менять food/training, модель, инфраструктуру или медицинские нормы.

Приёмка: синтетические аналоги двух реальных вопросов с загрязнённой историей;
старый маркер не становится свежим, WHOOP не исключает инфекцию, неизвестная
причина остаётся неизвестной; вопросы о свежих анализах и дневник продолжают
работать. Отдельный локальный прогон с реальной моделью без отправки в Telegram.

Граница применения приборов согласуется с [AASM](https://aasm.org/consumer-sleep-technology-position-statement/):
потребительский трекинг не заменяет медицинскую оценку. Усталость имеет разные
причины; это не готовый диагноз ([MedlinePlus](https://medlineplus.gov/fatigue.html)).
