# Завершение проверки состояния и медицинского импорта

TL;DR: выполнить уже согласованные две доработки, затем отправить три короткие сводки по настоящим данным в основной Telegram.

## Согласованный объём

Пользователь явно поручил завершить очередь медицинских документов и актуализировать страницу состояния после рекапа v0.1. Это завершение существующих сценариев из docs/healthcheck.md и docs/lab-extraction.md, не новый продуктовый выбор. Не добавляем сервисы, интеграции или новую архитектуру.

Страница /healthcheck читает только локальные данные: отдельные состояния основного/еды/тренировочного ботов, привязка конкретного профиля и свежесть опроса; диапазон фактов COROS и разового импорта Apple (вес/кандидаты тренировок); отдельные числа queued/running/waiting_cloud/cloud_in_flight/needs_attention, не смешивая страницы с показателями анализов. Ошибка/отсутствие данных не зелёный статус. Никаких клинических значений, токенов, исходных ошибок или чужого профиля. Время явно по Москве. Сохраняем прежние подключения и ссылки.

Медицинская очередь: сначала установить конкретные причины, затем устранить безопасно в рамках текущих разрешений. Не удалять исходники, не подтверждать медицинские кандидаты автоматически, не обходить дневной бюджет или ограждения неизвестного результата облака. Если нужен новый расход/новый доступ, сообщить точный остаток и запросить только необходимое решение.

Сводки: тренировки/COROS, сон/WHOOP, анализы/подтверждённые значения и проверенные исходники. По одному короткому сообщению на тему: вывод, 2–3 опорных наблюдения с периодом, один практический следующий шаг, ограничения. Сверить медицинские рекомендации с авторитетными источниками, не делать причинных диагнозов из трекеров. Сохранить расчёты/сводки локально приватно; отправить только в привязанный основной бот пользователя с постоянными ключами доставки. В Git только код/тесты/документация, не медицинские данные.

## Приёмка

Изолированные тесты профилей, отсутствующих/ошибочных/устаревших данных и отсутствия сетевых обращений на странице; текущие сценарии не ломаются. Операционная сверка очереди до/после с честным остатком. Живая страница показывает новые состояния. Три отдельные подтверждённые доставки либо явный неизвестный исход без слепого дубля.
