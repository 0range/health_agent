# Health Agent v1 — план реализации

> **Для быстрого просмотра:** шесть вертикальных срезов; каждый заканчивается работающим пользовательским сценарием. Полный состав v1 не урезается.

**Цель:** довести утвержденный дизайн до автономно работающего Health Agent на Mac.

**Подход:** PostgreSQL остается источником правды; интеграции складывают данные через единый provenance-контракт; Google Sheets и Metabase являются представлениями; Telegram и Health Agent работают только через ограниченный прикладной API. Реализация идет последовательно, чтобы неисправность обнаруживалась на маленьком сквозном сценарии.

## Срезы

1. **Локальный фундамент и один медицинский документ.** Один PDF проходит путь `файл → локальное хранилище → PostgreSQL → проверенные лабораторные строки → график Metabase`. Детальный план: `2026-09-04-health-agent-v1-slice-1-foundation.md`.
2. **Архив, Google Sheets и Gmail.** Drive читается рекурсивно и только на чтение; весь архив получает статус; медицинское письмо за последние семь дней автоматически поступает в тот же pipeline; анализы и очередь проверки публикуются в Sheets.
3. **WHOOP.** Официальный OAuth, полный доступный backfill, регулярное обновление без дублей, вес как текущий снимок и обзорный dashboard.
4. **Health Agent и Telegram.** Открытый вопрос выбирает релевантную историю, отделяет факты от гипотез, указывает источники и пробелы; Telegram также принимает документы и ручные наблюдения.
5. **Напоминания и автономная работа.** Предложение → подтверждение → отправка → перенос/выполнение; расписание, автоматические повторы, status и backup.
6. **Приемка v1.** Все пять продуктовых сценариев проходят на реальных данных; повторные синхронизации не создают дубли; после перезапуска Mac работа продолжается без ручного ремонта.

## Правило перехода

Следующий срез начинается после автоматических тестов и одного реального сквозного прогона текущего. Неудачный источник не останавливает остальные. Технические проблемы исправляются без участия пользователя; его действие требуется только для OAuth, значимой медицинской неоднозначности или подтверждения внешнего действия.

## Что не строим

Нет отдельного собственного UI, публичного сервера, Kubernetes, event bus, vector database и универсальной платформы коннекторов. Apple Health, Oura, COROS, TrainingPeaks, питание, среда сна и Calendar остаются в бэклоге.
