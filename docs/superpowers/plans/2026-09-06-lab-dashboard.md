# Laboratory dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking.

**Goal:** Show blood-test history with understandable separate parameter/unit graphs and exact laboratory references, never one mixed-unit curve.

**Architecture:** Add a bounded laboratory dashboard provisioner alongside the existing WHOOP provisioner, reusing Metabase connection/client helpers. Queries read verified dated observations only and isolate each profile. Existing WHOOP cards are untouched.

**Tech Stack:** Existing SQLAlchemy/PostgreSQL, Metabase local API, httpx mock transport, pytest.

## Global Constraints

- No live services, credentials, schema changes, synthetic production data, or shared CLI/panel edits in implementer. Root composes and deploys after review.
- User authorizes autonomous parallel implementation; no additional user acceptance gate during development.
- No guessed reference intervals or unit conversions, no interpretation presented as diagnosis, no hidden omission of units, dates or source identity.
- Only verified finite numeric dated results; pending/rejected/superseded, unsafe documents and future dates excluded. Preserve multiple measurements on the same day as individual records, never average or sum results.
- Each chart has exactly one analyte and one normalized unit. Graphs may show source lower/upper limits only when source value and normalized value represent the same physical scale; otherwise keep original reference text in detail table without a numeric overlay.
- Existing WHOOP dashboard, unrelated/user-created Metabase cards, and archived records must remain intact. No deletion by name alone.

### Task 1: Profile-bound lab dashboard with separate unit families

**Files:** create `src/health_agent/lab_dashboard.py`, `tests/test_lab_dashboard.py`, `docs/lab-dashboard.md`. Modify `src/health_agent/metabase.py` only to expose a needed reusable helper or narrow verified legacy-card reconciliation; avoid rewriting bootstrap/default API. Existing WHOOP helper code may be read but not copied wholesale or changed.

**Interfaces:** Export immutable `LabSeries(canonical_name: str, label: str, unit: str)`, `lab_card_specs(profile_id: UUID, series: tuple[LabSeries,...])` and `bootstrap_lab_dashboard(settings, profile_id: UUID, *, transport=None, engine=None)` returning dashboard_id/card_ids/dashboard_url. Use existing `MetabaseClient`, `_ensure_collection`, `_ensure_database`, `ensure_dashboard_reader` and verified view schema. Query discovery through passed engine/session is read-only.
