# Визиты к врачу

Модуль хранит визиты, вопросы и записанные пользователем ответы в PostgreSQL, отдельно для каждого профиля. Он не записывает на приём, не создаёт событие календаря и не отправляет медицинские данные внешним сервисам.

В Telegram доступны `/visits`, `/visit_new YYYY-MM-DDTHH:MM | название`, `/visit КОД`, `/visit_prepare КОД`, `/visit_question КОД текст`, `/visit_answer КОД текст`, `/visit_done КОД`, `/visit_cancel КОД`, `/visit_move КОД YYYY-MM-DDTHH:MM`. Новый визит длится 60 минут; время вводится в Europe/Moscow. Перенос сохраняет длительность и часовой пояс. Список показывает до 20 визитов, сначала предстоящие запланированные.

Подготовка один раз добавляет пять общих вопросов для обсуждения с врачом. Она показывает до десяти проверенных анализов с известной датой не позднее сегодняшней: исходное название, значение, единицу, референс, ID документа и страницу. Дата забора имеет приоритет над датой выдачи. Непроверенные значения исключаются; их количество указано отдельно. Это не медицинское заключение и не подтверждение новых показателей. Записанный ответ — текст пользователя, не автоматический ответ врача.

После завершения визита записи сохраняются и можно добавлять новые вопросы/ответы. Отменённый визит доступен для чтения; новые записи запрещены. Завершённые и отменённые визиты нельзя перенести или открыть заново. API не предоставляет удаления визитов и редактирования/удаления заметок. Повтор команды создания или заметки с тем же ключом возвращает сохранённую запись; другой профиль или изменённое содержимое с тем же ключом отклоняется.

Текст вопроса/ответа ограничен 10 000 символами, название — 200, ключи повтора — 200, размер выборки — 100. Детали Telegram ограничены 12 000 символами; обрезка явно помечается. Метод `notes` возвращает первые 100 записей по времени (или меньший явно заданный лимит). Полные записи остаются в БД.

## Подключение

Экспортированы `DatabaseVisitCommands(engine).handle(context, text)`, `VisitRepository(session)`, `prepare_visit(session, profile_id, code)` и Typer `health_agent.visits.cli.app`. Контекст Telegram должен быть проверен существующим слоем аутентификации; профиль берётся только из него. Главный CLI может зарегистрировать `app.add_typer(visit_app, name="visit")`. Общая композиция выполняется отдельно.

CLI предоставляет `create`, `list`, `show`, `prepare`, `note`, `complete`, `cancel`. Для каждой команды обязателен `--profile-id UUID`. Пример после регистрации:

```text
health-agent visit create --profile-id UUID --title "Приём" --when 2026-10-05T10:00
health-agent visit prepare КОД --profile-id UUID
health-agent visit note КОД --profile-id UUID --kind answer --text "Записанный ответ"
```

Для воспроизводимого повтора используйте `--creation-key` или `--action-key`; без них CLI генерирует новый ключ. `create` поддерживает `--timezone`, `--duration-minutes` (1–1440), `--source-document-id` только для документа того же профиля. Неоднозначное/несуществующее местное время отклоняется.

Миграция `0010_doctor_visits` ответвляется от `0008_lab_extraction`; интегратор объединяет её с параллельной ветвью напоминаний. Внешние ключи БД дополнительно обеспечивают принадлежность документа и заметок профилю. Откат отказывается удалять непустые таблицы; проверки миграции используют только одноразовый тестовый PostgreSQL.
