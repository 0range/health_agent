# Локальная management-панель

Панель запускается только на компьютере владельца и слушает фиксированный адрес
`http://127.0.0.1:8766`. Она не публикуется в локальной сети, не открывает
браузер и не содержит внешних ресурсов.

```bash
uv run health-agent panel serve
```

`PANEL_HOST` по умолчанию и по проверке равен `127.0.0.1`: любой другой адрес,
включая `0.0.0.0`, отклоняется при запуске. `PANEL_PORT` по умолчанию равен
`8766` и может быть задан в `.env` в диапазоне 1–65535.

## Что реализовано

- ежедневная сводка выбранного профиля: `Подключено`,
  `Синхронизация ещё не запускалась` или `Нужно действие`;
- шесть понятных карточек: WHOOP, Google Drive, Gmail, Telegram, напоминания и
  локальная база;
- просмотр списка локальных профилей;
- создание нового локального профиля;
- просмотр безопасных, профиль-изолированных карточек статуса WHOOP, Gmail,
  Telegram и Google Drive;
- добавление или замена одной или нескольких входящих папок Google Drive для
  выбранного профиля: вставьте ссылку или ID, по одному значению на строке;
- человеческое время последней успешной синхронизации и конкретное следующее
  действие;
- ссылка `Дашборды` на локальный Metabase и понятный placeholder Google Таблицы
  до подключения соответствующей интеграции.

UUID профиля, account ID, точное ISO-время, безопасный код ошибки и CLI-команда
скрыты в раскрываемых `Технической информации` и `Подробностях`. Для обычной
проверки состояния они не нужны.

Это не интерфейс медицинских данных: он не показывает показатели, значения,
документы, имена файлов, тела сообщений, пароли или OAuth-токены. Создание
профиля и все состояния коннекторов привязаны к выбранному `profile_id`; данные
другого профиля не используются как запасной вариант.

## Чего в панели нет

Панель не содержит кнопок OAuth, sync, отключения аккаунта или удалённого
действия. Открытие страницы читает только локальный статус выбранного профиля;
она не обращается к WHOOP, Gmail, Telegram или Google Drive API. OAuth-клиент и токены не
читаются при построении сервера — соответствующее локальное состояние проверяется
только при запросе страницы. SQLite-state Telegram также не создаётся при
построении сервера: его адаптер создаётся только после выбора существующего
профиля и проверки локальных учётных данных при запросе статуса.

Раскройте `Настройки Google Drive`, чтобы добавить или заменить папки. Форма
меняет только локальный список read-only входящих папок.
Сохранение заменяет текущий список для выбранного профиля, сохраняет уже
подтверждённую привязку Google-аккаунта и сбрасывает курсор, если папки реально
изменились. Авторизация, обход файлов и синхронизация остаются явными CLI-действиями.

Карточка напоминаний читает только профильные агрегаты: сколько предложений ждёт
подтверждения, сколько запланировано и сколько пора отправить. Названия, причины
и другой медицинский текст на страницу не попадают. Карточка базы выполняет
только локальную проверку доступности без подсчёта медицинских записей.

## Передача действий в CLI

Выполняйте авторизацию и синхронизацию явно в Terminal для конкретного профиля:

```bash
uv run health-agent whoop auth --profile-id PROFILE_UUID --account main
uv run health-agent whoop sync --profile-id PROFILE_UUID --account main
uv run health-agent gmail configure PROFILE_UUID personal
uv run health-agent gmail auth PROFILE_UUID personal
uv run health-agent gmail sync PROFILE_UUID --account-id personal
uv run health-agent drive auth PROFILE_UUID
uv run health-agent drive sync PROFILE_UUID
uv run health-agent telegram status --profile-id PROFILE_UUID
```

У каждого человека собственный `PROFILE_UUID`; подставляйте UUID профиля,
созданного через панель или `uv run health-agent profile create "Имя"`. Более
полные инструкции находятся в [WHOOP runbook](runbooks/whoop.md),
[Gmail integration guide](integrations/gmail.md) и
[Telegram integration guide](integrations/telegram.md), а также
[Google Drive integration guide](integrations/google-drive.md).

## Проверочный статус

Панель проверена только автоматическими тестами с disposable локальными
фикстурами и mocked-интерфейсами. Live acceptance не проводился: тесты не
используют реальные OAuth credentials, токены, пользовательские данные или
внешние connector-сервисы.
