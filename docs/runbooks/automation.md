# Фоновая автоматизация на macOS

## TL;DR

Один пользовательский LaunchAgent запускает WHOOP, Gmail и Google Drive, затем
включённые profile jobs извлечения лабораторных кандидатов, затем Sheets каждые
четыре часа. Он не содержит секретов, не смешивает профили и продолжает работу,
если отдельный источник завершился ошибкой или завис.

## Подготовка

Сначала настройте нужные профили и один раз авторизуйте их обычными командами
WHOOP/Gmail/Drive. Создайте абсолютный приватный файл окружения и ограничьте его
права:

```bash
chmod 600 /полный/путь/к/.env
```

Относительный путь, symlink, каталог и файл с иными правами отвергаются. В plist
попадает только путь к `.env`; значения из него туда не копируются.

## Команды

Проверить полный последовательный прогон вручную:

```bash
uv run health-agent automation sync --env-file /полный/путь/к/.env
```

`--full` принудительно запрашивает полную сверку всех поддерживающих её целей.
Без флага первая успешная сверка каждой пары профиль/аккаунт полная, следующие —
инкрементальные, а через семь дней снова полная. Неуспешная, отложенная или
прерванная полная сверка не переносит контрольную дату.

Посмотреть plist без установки, затем явно установить:

```bash
uv run health-agent automation render --env-file /полный/путь/к/.env
uv run health-agent automation install --env-file /полный/путь/к/.env
uv run health-agent automation status --env-file /полный/путь/к/.env
```

Остановить расписание, сохранив plist и состояние:

```bash
uv run health-agent automation stop --env-file /полный/путь/к/.env
```

Остановить и удалить только два управляемых plist:

```bash
uv run health-agent automation remove --env-file /полный/путь/к/.env
```

## Поведение и файлы

- Label: `com.orange.health-agent.sync`.
- Интервал: 14 400 секунд; `RunAtLoad` включён.
- Таймаут каждого источника: 1 800 секунд.
- Глобальный lock неблокирующий: второй запуск честно завершается как
  `safe_error=already_running`. Собственные lock-и коннекторов защищают от
  пересечения с ручным sync.
- Состояние: `data/automation/state.json`.
- Проверяемый plist: `data/automation/launchd/com.orange.health-agent.sync.plist`.
- Установленный plist: `~/Library/LaunchAgents/com.orange.health-agent.sync.plist`.
- Логи: `data/automation/logs/stdout.log` и `stderr.log`. После 5 MiB сохраняется
  только одна предыдущая генерация `.1`.

Каталоги автоматизации имеют права `0700`, управляемые файлы — `0600`. В логах
есть только источник, UUID профиля, слот аккаунта, режим, статус и фиксированный
код ошибки. Вывод коннектора, медицинские значения и текст исключений
отбрасываются.

`failed` и `timed_out` дают ненулевой код после обработки всех целей. `deferred`
и `already_running` не считаются аварией. Повреждённая конфигурация одного
источника не блокирует остальные источники.

Полностью ненастроенный источник не создаёт job и не считается ошибкой.
Настроенный Gmail-аккаунт или Drive-профиль без завершённого OAuth получает
`status=deferred safe_error=oauth_not_ready`: сеть не вызывается, запуск остаётся
успешным, а первая полная сверка остаётся ожидающей. Повреждённый token, ошибка
OAuth после авторизации и ошибка самого коннектора остаются `failed`.

## Границы этого этапа

`lab-extract configure PROFILE_UUID` включает отдельный bounded post-sync worker:
новые Drive/Gmail и уже завершённые Telegram импорты подхватываются на следующем
прогоне, все кандидаты остаются needs_review. Cloud требует отдельного `--openai`.
Extraction не имеет full-режима, не вызывает API внутри connector транзакций
и не сбрасывает budget/retry fences между запусками. См. [lab extraction](../lab-extraction.md).

Автоматизация не запускает OAuth, не устанавливается во время тестов и не
включает Telegram-daemon в этот последовательный runner. Telegram имеет отдельный
LaunchAgent; см. [интеграцию Telegram](../integrations/telegram.md).
